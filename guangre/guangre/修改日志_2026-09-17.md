## 3. 详细变更说明

### 3.1 DAC 时钟域统一（Critical）

**原问题**：DDS/`da_clk` 在 25 MHz，`sin_amp_offset` 与 `da_data` 在 50 MHz，跨时钟直接出板。

**修改**：

- `sin_amp_offset` 改到 `clk_dac`（25 MHz）时钟域
- `da_data` / `da_data1` 在 `clk_dac` 再寄存一拍后输出
- `da_clk` / `da_clk1` = `clk_dac`

### 3.2 `sin_amp_offset` 饱和修复（Critical）

**原问题**：`saturated` 为 10 位无符号，`>1023`/`<0` 判断恒假；负向还写成 `1023`。

**修改**：

- 用 42 位有符号中间量 `level` 做比较
- 正向钳位到 1023，负向钳位到 0
- 注释明确：`scale_factor` 为 1~100（增益 /100），`bias` 为 0~1023

### 3.3 UART 发送握手修复（Critical）

**原问题**：`send_en` 保持为高时，发送完成后可能立即重发同一字节。

**修改**（`uart_send.v`）：

- 仅在 `send_en` **上升沿**启动一次发送
- `tx_done` 改为单周期脉冲

### 3.4 协议校验与 Error 应答（High）

**原问题**：DUTY/AMPL 等越界仍回 `Command Success!`。

**修改**（`uart_commend.v`）：

| 指令 | 校验 |
|------|------|
| `TRIG` / `T_LIGHT` | 禁止 0 |
| `DUTY` / `D_LIGHT` | 0~100000 |
| `AMPL` / `AMPL_LIGHT` | 1~100 |
| `OFFST` / `OFFSET` / `OFFSET_LIGHT` | 0~1023 |

- 校验失败：不更新寄存器，回 `Command Error!\r\n`
- `update_flag_*` 改为单周期脉冲
- 指令名过长保护
- 通道0 偏置同时接受 `OFFST:` 与 `OFFSET:`
- 注释明确：`SINE` / `SINE_LIGHT` 下发的是 **DDS PINC**，不是 Hz  
  \(f_{out}=PINC \times 25\,\mathrm{MHz}/2^{48}\)

### 3.5 触发模块保护（High）

**修改**（`clk_trig.v`）：

- `trigger_freq==0` 时保持原频率，避免除零
- `period` 最小值钳到 2
- 乘法改用寄存后的 `current_duty`
- A 口按 IP 32 位宽度截断/饱和

### 3.6 接上 `clk_light`（High）

**原问题**：端口与约束存在，但逻辑被注释。

**修改**：例化第二路 `clk_trig`，由 `T_LIGHT` / `D_LIGHT` 驱动 `clk_light`。

### 3.7 约束完善（Medium）

**修改**（`pin.xdc`）：

- 为 `da_clk` / `da_clk1` 增加 `create_generated_clock`（÷2）
- 整理注释

### 3.8 其它

- `clk_fenpin`：修正“默认 4 分频”错误注释
- `da_wave_send`：标明废弃，勿再例化
- 顶层显式声明 DDS 相关 wire，去掉隐式线网

## 4. 协议速查（修改后）

```
SINE:<PINC>\r
SINE_LIGHT:<PINC>\r
TRIG:<mHz>\r          # 80000 = 80 Hz，禁止 0
DUTY:<0..100000>\r    # 50000 = 50%
AMPL:<1..100>\r
AMPL_LIGHT:<1..100>\r
OFFST:<0..1023>\r     # 或 OFFSET:
OFFSET_LIGHT:<0..1023>\r
T_LIGHT:<mHz>\r       # 驱动 clk_light
D_LIGHT:<0..100000>\r
```

成功：`Command Success!\r\n`  
失败：`Command Error!\r\n`
