# 修改日志：时序违例修复（2026-10-28）

## 现象

实现后 WNS = -0.146 ns，TNS = -0.209 ns，3 个失败端点，全部是
`guang_0/inst/u_clk_trig/high_time_reg_reg[*]/D`。

## 原因 1：`clk_trig.v` 单周期 64 位除法

```verilog
high_time_reg <= mult_result[63:0] / 64'd100_000;
```

常数除法被综合成 43 级组合逻辑（31 个 CARRY4），数据路径 19.8 ns，
50 MHz（20 ns）下本来就只剩零点几 ns 余量，布局稍有变化就违例。
与这次的幅度/偏置修改无直接关系，是早就处在边缘的路径。

**修复**：改为 64 拍移位相减除法器循环计算，每拍只有一个 18 位比较/减法。
`high_time` 每 65 个时钟（约 1.3 µs）刷新一次，对触发信号没有可见影响。

顺带修正：`CLK_FREQ * 1000` 改为 64 位常量 `CLK_X1000`。
Vivado 综合对这个常数本来就算对了（已验证为 5e10），但仿真器按 32 位计算会溢出，
导致仿真结果和硬件不一致。

## 原因 2：`clk_dac` 没有时钟约束（隐藏问题）

`clk_dac` 是 `u_clk_fenpin/clk_out_reg` 寄存器分出来的 25 MHz，原来没有约束，
报告里 439 个寄存器是 `no_clock`：DDS、`sin_amp_offset`、DAC 输出寄存器
**完全没有做时序检查**，“时序满足”并不代表它们没问题。

**修复**：`design_pin.xdc` 增加

```tcl
create_generated_clock -name clk_dac \
    -source [get_pins -hier -filter {NAME =~ *u_clk_fenpin/clk_out_reg/C}] \
    -divide_by 2 \
    [get_pins -hier -filter {NAME =~ *u_clk_fenpin/clk_out_reg/Q}]
```

用旧的布线结果加上这条约束复查：

| 路径 | 结果 |
|---|---|
| clk_dac 内部 | setup 余量约 31 ns，没问题 |
| clk_dac → clk_fpga_0 | 满足 |
| clk_fpga_0 → clk_dac（UART 参数 → DDS/幅度偏置寄存器） | setup 满足；**hold 约 -2.9 ns，132 条** |

hold 违例的原因：`clk_dac` 从寄存器出来再进 BUFG，比 `clk_fpga_0` 晚到约 3 ns。
原来没有约束时 Vivado 根本不会去修。加上约束后重新实现，布线器会自动绕线补延时
修掉 hold（setup 余量有将近 20 ns，空间足够）。

## 验证

- `sim\run_tb_clk_trig.bat`：IP 用行为模型代替，覆盖多组频率/占空比、
  周期饱和、0%/100% 占空比、实测占空比，结果 `ALL TESTS PASSED`。
- 需要重新综合 + 实现。检查实现后报告：WNS ≥ 0、WHS ≥ 0，
  并且 `check_timing` 里 `no_clock` 为 0。

## 如果重新实现后 clk_fpga_0 → clk_dac 的 hold 仍然修不掉

根本解决办法是不再用逻辑分频出来的时钟：
DDS / 幅度偏置 / DAC 输出全部直接跑在 50 MHz 的 `sys_clk` 上（AD9708 支持 125 MSPS），
这样整个 PL 只有一个时钟域。代价是 DDS 频率公式变为 `f = PINC × 50MHz / 2^48`，
上位机的 PINC 换算要同步修改。
